# Правила и инструкции для разработки (AGENTS.md)

## Критический подход к туториалам и обучающим материалам
- **Никогда слепо не повторять плохие практики из уроков/туториалов:** Если в обучающем материале предлагаются небезопасные или антипаттерные решения (например: хардкод паролей/секретов в коде, закомментирование секретов вместо удаления, отключение валидации, отсутствие .gitignore для секретов) — **сразу жестко критиковать такое решение с первой секунды**.
- **Предлагать production-ready best practices:** С первого же ответа показывать, как делать правильно по современным стандартам индустрии и безопасности.
- **Безопасность данных и секретов:** Любые секретные ключи, токены и пароли должны храниться исключительно в переменных окружения (.env), никогда не коммититься в Git и не оставаться в комментариях публичных конфигурационных файлов.
